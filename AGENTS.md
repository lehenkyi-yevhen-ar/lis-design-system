# Ліс — правила роботи з репозиторієм

Дизайн-система «Ліс»: токени, CSS-компоненти, vanilla-JS поведінка, сайт-документація. Брендбук (колір, типографіка, голос, скло, рух) — розділ «Огляд» у `index.html`; його джерело живе в README артефакта на claude.ai, а в репо — як готовий HTML у blob `D.readme`.

## Жорсткі правила інтерфейсу

- Кольори, відступи, радіуси, шрифти, `z-index`, тривалості — лише через семантичні токени (`--color-*`, `--space-*`, `--radius-*`, `--font-*`, `--z-*`, `--duration-*`). Шкали (`--sand-500`, `--forest-300`) напряму не використовувати.
- Одна `btn--primary` на екран. `btn--accent` — лише промо. `btn--danger` — лише з підтвердженням у `Modal`.
- Статус (success/warning/error/info) завжди зі словом чи іконкою, не лише кольором.
- Ermilov — тільки заголовки від 18px. Текст, кнопки, поля — KyivType Sans.
- Текст на заливці — лише парний токен `on-*`. Текст ≥4.5:1, рамки/фокус/іконки ≥3:1 в обох темах.
- Зона натиску ≥44×44px, кнопка-іконка з `aria-label`, `prefers-reduced-motion` поважати.
- Mobile-first: брейкпоінт телефона 640px, сайт-документація перемикається на tabbar/шторку на 900px. Горизонтального скролу на 390px немає.
- Фреймворки (React, Vue): джерело правди — `tokens.css` + `components/bundle.css`; компонент = обгортка над тими ж класами, поведінка через `DS.init(scope)` у `useEffect`. Деталі — розділ «Фреймворки» в брендбуку.
- React-шар живе в кінці `components/bundle.js` (другий IIFE, потребує `window.React`): `DS.Button`, `DS.Badge`, `DS.Field`, `DS.useDS`. Новий React-компонент лише складає наявні класи з `bundle.css` (без власних стилів у JS), має `<Name>Props` в `components/index.d.ts` і запис в заголовку `@ds-bundle`. Живий приклад — `demo/react.html`.

## Як влаштований репозиторій

- `tokens.json` — єдине джерело значень. `tokens.css` генерується з нього (у кожному блоці теми — `var(--шкала)`).
- `index.html` містить один рядок `const D={...};` (токени, брендбук HTML, компоненти з README-HTML, мобільний розділ). Його треба перегенерувати щоразу, коли змінюються `tokens.json`, README компонента, `mobile.md` чи брендбук. Серіалізація «як у Python»: `json.dumps(D, ensure_ascii=False)` з екрануванням `</` → `<\/`, інакше диффи величезні.
- `demo/*.html` (крім `mobile.html`) — старі самодостатні знімки зі своїм CSS/JS; мобільні виправлення — у доданому `<style id="mobile-patch">`. `demo/mobile.html` підключає справжні `tokens.css` і `bundle.*`.
- `?v=…` у посиланнях на CSS/JS/iframe — cache-bust для GitHub Pages; змінюючи CSS/JS/токени, піднімайте його в усіх HTML однаково.
- Робочі файли — з LF (git `autocrlf` увімкнений; `git stash` перетворює на CRLF).

## Перед комітом

```
python scripts/check.py
```

Перевіряє контраст токенів в обох темах, збіг `tokens.css` і `index.html` з `tokens.json`, сирі hex/`font-family`/`z-index` у `bundle.css`, єдиний cache-bust і LF. Код виходу ≠ 0 — не комітити.

## Синхронізація

- Кожна зміна йде і в репо, і в артефакт «Ліс» на claude.ai (тип «Design System», файли під `project/`). `tokens.css`, `index.html`, `scripts/`, `AGENTS.md` у артефакт не потрапляють.
- `git push` — лише після явного дозволу власника.
